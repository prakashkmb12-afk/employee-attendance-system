# REVIEW.md

List of defects found and resolved in the starter `app/main.py`:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Global setup / Startup (Lines 22-23) | No database indexes were created on startup. Duplicate employees and duplicate punches could be inserted under concurrent requests, and large collection scans occurred on 100k records. | Inserting duplicate `emp_code` or `(emp_code, date)` succeeded without uniqueness guarantees. Queries performed `COLLSCAN`. | Added FastAPI `lifespan` context manager to idempotently create unique indexes on `employees.emp_code`, `attendance_logs.(emp_code, date)`, and query indexes on `department`, `date`, `status`, and `joined_on`. |
| 2 | `compute_late_minutes` (Lines 33-38) | Grace period check compared integer minutes instead of elapsed seconds, and naive timezone replacement corrupted UTC timestamps. At 09:40:01 (shift 09:30), elapsed seconds is 601; `int(601/60)` is 10, and `10 > 10` is False, returning 0 instead of 10. | Test with punch-in at `09:40:01` (shift `09:30`) returned `0` late minutes instead of `10`. | Rewrote helper to compute `diff_sec = (punch_in_ist - start_dt).total_seconds()`. If `diff_sec > 600` (strictly > 10:00), returns `int(diff_sec // 60)` from shift start; else `0`. |
| 3 | `compute_work_hours` (Lines 40-42) | Used Python's built-in `round()`, which performs Banker's rounding (round-half-to-even) instead of mandatory R4 round-half-up. Also did not truncate instants to whole seconds before calculation. | Duration of 2.125 hours rounded to 2.12 instead of 2.13. | Converted truncated seconds difference using `decimal.Decimal` and quantized with `ROUND_HALF_UP` to two decimal places. |
| 4 | `compute_overtime` (Lines 44-48) | Ignored the 30-minute minimum threshold (R3) and placed `shift_end` on the punch-in date even for overnight shifts where `shift_end <= shift_start`. | Punch-out 10 minutes after shift end returned `10` instead of `0`. An overnight shift ending at 06:00 compared punch-out against 06:00 of the previous day, yielding > 24 hours overtime. | Added overnight shift check (adding 1 calendar day to `shift_end` when `shift_end <= shift_start`). Enforced that overtime is only counted if `minutes >= 30`, otherwise returning `0`. |
| 5 | `GET /health` (Lines 72-74) | Returned static `{"status": "ok"}` with HTTP 200 without checking if MongoDB was reachable. | When MongoDB was stopped or disconnected, `/health` still reported 200 OK instead of 503 Service Unavailable. | Added `client.admin.command("ping")` inside a `try/except` block, raising `HTTPException(503, "Database unavailable")` if the ping fails. |
| 6 | `POST /employees` (Lines 77-85) | Performed check-then-insert (`find_one` then `insert_one`), which is vulnerable to concurrency race conditions. Accepted invalid input patterns and equal shift times. Returned `created_at` as a Python datetime object instead of epoch milliseconds. | Concurrent identical employee creation requests both succeeded or threw uncaught 500 errors. Invalid `emp_code` or equal shift start/end passed validation. Response body had datetime string instead of integer epoch ms. | Enforced Pydantic schema validation (`EmployeeCreate` with regex and validator ensuring `shift_start != shift_end`), inserted directly with unique index catching `DuplicateKeyError` to return 409, and formatted `created_at` as epoch milliseconds integer without `_id`. |
| 7 | `GET /employees` (Lines 88-96) | Off-by-one pagination bug: `skip = page * page_size` skipped the first page entirely (page 1 skipped 20 items). `total` counted `{}` instead of the filtered query `q`. Results were unsorted. | Requesting `page=1` returned items 21–40. Filtering by department still showed total count of all employees across all departments. | Changed offset to `skip = (page - 1) * page_size`, computed `total = db.employees.count_documents(q)`, and sorted cursor by `[("emp_code", 1)]`. |
| 8 | `POST /attendance/punch-in` (Lines 100-122) | Crashed with unhandled 500 `TypeError` when an employee was not found. Concurrency race condition on check-then-insert. Ignored overnight shift date resolution (R1). Returned internal MongoDB `id`. | Punch-in for non-existent employee returned 500 instead of 404. Punch-in at 01:30 for overnight shift 22:00-06:00 was assigned to the current day instead of previous day. Response included `{"id": "..."}`. | Validated employee existence (returning 404 if missing), resolved overnight attendance date using `get_attendance_date`, caught `DuplicateKeyError` on `(emp_code, date)` unique index to return 409, and removed `id` / `_id` from response. |
| 9 | `GET /attendance` (Lines 124-151) | Loaded all documents into Python memory via `list(db.attendance_logs.find(q))` and sorted with Python's `.sort()`, causing severe performance degradation and memory exhaustion on 100k docs. Sorting was unstable without secondary sort. Permitted `date_from > date_to`. Returned `id` (ObjectId). | Listing 100k records consumed huge memory. Records with identical dates had non-deterministic ordering across page boundaries. `date_from > date_to` returned 200 instead of 422. | Replaced with indexed database cursor using `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`, validated `date_from <= date_to` (returning 422 if inverted), and formatted records with epoch milliseconds and no `id`. |
| 10 | `POST /attendance/punch-in` timestamp parsing (Line 102) | Used `datetime.fromtimestamp(body.punched_at / 1000)` which interpreted the timestamp in the server's local machine timezone instead of UTC, and did not truncate instants to whole seconds per R1. | Timestamps with non-zero milliseconds (e.g., .900) produced inconsistent seconds. Server timezone offsets altered UTC instants. | Implemented `truncate_ms` (`(ms // 1000) * 1000`) and converted using timezone-aware UTC datetime `datetime.fromtimestamp(trunc / 1000.0, tz=timezone.utc)`. |

### What was examined and confirmed NOT to be a defect:
- **FastAPI dependency and route setup**: The basic FastAPI application structure and router decorators were standard and appropriate.
- **Environment variable handling via `python-dotenv`**: `load_dotenv()` correctly loads a local `.env` while preserving real environment variables set by the runner (`os.getenv`), satisfying the configuration contract.
- **Pydantic model usage**: Pydantic v2 validation and `.model_dump()` approach is modern, clean, and appropriate for request parsing.
